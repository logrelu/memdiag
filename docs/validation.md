## Goal 1: does memdiag find injected memory failures at the right turn?

Each case is one or more clean LongMemEval-S sessions with exactly one injected failure at a known turn, plus a paired control (same sessions, a look-alike that is not a failure). **Recall**: the case has a finding of the right type that its paired control does not also have on the same turn, so background findings in the base conversations can't count as detection. **Exact turn**: a finding of the right type on the gold turn (the reply with the injected failure; for repairs, the assistant turn the user repairs). **False positives**: controls with any finding of their type, including background, so this rate is pessimistic. 95% Wilson intervals. Method: `docs/plans/M6.md`.

## Threats to validity

- Injected failures are short and explicit; real failures are subtler. Treat recall here as an upper bound for real logs. External validity (real labels, human agreement) is Goal 2.
- Base conversations are LLM-generated (LongMemEval). Some phrasings overlap with detector rules; held-out templates include phrasings the rules were not written for.
- In LLM mode one local model is extractor and judge; a second judge family has not been run yet.
- Controls test specific look-alikes, not every way a detector can misfire on real logs. One held-out re-ask control (`r_n2`, "Is the weather nice where you are this week?") is arguably a location question; it is kept so held-out cases are unchanged, and controls that fired are listed by id.
