# M4: the fact ledger

Roadmap row M4. Branch `m4-ledger`, one PR.

## Goal
One ledger per log: what each user said about themselves, when, in which turn, and in their exact words, with
updates and deletions linked. It is built from rules plus an optional LLM extractor (M3 judge). It is what M5's
detectors check assistant turns against. The walkthrough's failure (`usermyself.city` vs `user.city`, so Denver
and Austin never met) must be impossible by construction.

## Changes
1. **`memdiag/text.py`**: move the quote helpers (`sentence`, `numbers`) out of `detect.py`, unchanged.
   `detect.py` imports them.
2. **`memdiag/ledger.py`**
   - `LedgerItem`: `item_id`, `user_id`, `key` (`subject.attribute`), `subject`, `attribute`, `value`,
     `source_turn`, `ts`, `quote`, `extractor` (`rules`, `llm`, or `rules+llm`), `superseded_by`, `revoked_at_turn`.
   - `normalize_key(subject, attribute)` is deterministic:
     - subjects such as `user`, `I`, `me`, `myself` and `user|myself` all become `user`;
     - `my daughter` becomes `daughter`;
     - attributes become lowercase snake_case, with a small synonym table (location/home_city/residence ->
       city, salary -> income, company/workplace -> employer, job/occupation/role -> job_title).
   - `normalize_value` compares values case- and punctuation-insensitively, and numbers by value
     (`$140k` == `140000`).
   - `build_ledger(events, judge=None)` walks user turns in time order:
     - rule facts and deletions first, quoted with the sentence that holds the value;
     - then the LLM (`extract_facts` v1), but only for messages that pass a cheap filter: a first-person
       statement, not only questions;
     - LLM facts whose quote is not in the message (ignoring case and whitespace) are dropped and kept in
       `ledger.dropped` for audit;
     - rule and LLM facts with the same key and value in the same turn merge into one item;
     - a new value for a key sets `superseded_by` on the previous item; the same value restated does not;
     - a deletion request sets `revoked_at_turn` on the key's live item. A later restatement starts a new
       live item.
   - Queries: `current(user, key, before_turn)`, `history(user, key, before_turn)`, `items_for(user)`, `to_rows()`.
     A turn is an event index, and order follows (ts, index).
   - `ledger.stats`: messages seen, messages sent to the LLM, items, and dropped items.
3. **CLI**: `memdiag ledger LOG [--model qwen2.5:7b] [--cache DIR] [--out ledger.jsonl]`. Without `--model`
   it uses rules only. It prints judge usage at the end.
4. **Docs**: the STABILITY ledger fields, CHANGELOG, CLAUDE layout.

## Tests (FakeJudge, no network)
- `tests/fixtures/ledger_cases.json` holds 20 or more hand-written cases. Each gives messages, scripted LLM
  output per message, and the expected current values, supersessions, revocations and drop count. They cover:
  rules only, LLM only, both agreeing, synonyms, subject variants, a relation subject, an update, a restated
  same value, a numeric-equal restatement, a deletion, a restatement after deletion, invented quotes,
  case- and whitespace-tolerant quotes, a question skipped by the filter, assistant turns ignored, two users
  kept apart, several facts in one message, an empty reply, a malformed reply, and an unknown subject.
- `normalize_key` and `normalize_value` unit tests.
- The walkthrough regression: "We just moved to Denver" followed by "we relocated to Austin" must give one
  key, with Denver superseded by Austin.

## Out of scope
Constraint extraction and `CONSTRAINT_DROP` move to M5 alongside their detector, because a constraint's scope
and revocation are judged against assistant turns. Switching the legacy detectors from `Timeline` to the
ledger also happens in M5.
